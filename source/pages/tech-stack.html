WeYield · technical architecture · Sept 2026

A stack two engineers can run at three in the morning.

Every choice here is constrained by one fact: two engineers are building and operating this while five others keep the existing product alive.

That single constraint eliminates most of what a bigger company would pick — and it happens to produce a better system, because there is no room for anything that is not load-bearing.

The new stack is additive. The integrations, the forecasting core and the rate-shop scrapers are never rewritten.

The one thing I could not check

I do not know what WeYield runs today — .NET, Java, PHP and Python are all plausible for a European vertical SaaS of this age. Confirm it before acting on anything below.

It changes less than you would think. The new stack sits beside the old one and reads from a shared warehouse, so the languages need not match. The only real question is whether the existing product can expose a scheduled extract and an API for write-back — and if it cannot, that is the first week's work.

Seven rules that answer most future questions

Write these down. They resolve the next fifty technology arguments without a meeting, and they are the reason the stack below looks unfashionably plain.

1
If two engineers cannot debug it at 3am, do not run it.Eliminates Kubernetes, microservices, Airflow and most of the agent-framework ecosystem in one line.
2
Buy the undifferentiated, build the moat.Buy email, auth, hosting, monitoring. Build the facts builder, the rules engine and the verifier. Nothing else is defensible.
3
One language for the new stack.Python on the server, TypeScript in the browser. That is two, and two is the limit.
4
Boring database, interesting product.Postgres until it genuinely hurts — and at 120 accounts it will not.
5
Every AI call has a deterministic check around it.No exceptions, on any surface, ever. This is the product promise expressed as architecture.
6
EU region, or it does not ship.French company, EU customers. It also turns the DPA conversation from ten pages into one.
7
Types everywhere.A real share of this code will be written with AI assistance, and typed codebases make that dramatically more effective. This is now an architectural decision, not a preference.

How the two stacks live together

The warehouse is the seam. The old stack writes to it on a schedule; the new stack reads from it and keeps its own tables.

The one hard rule: the new stack never writes to the old database. When it needs to change a rate, it calls the existing API — the same path a human would take.

The stack, layer by layer

Read the right-hand column first. Three things are built and everything else is bought — and those three are precisely the ones a competitor cannot copy by purchasing the same components.

Three calls most teams get wrong

Each of these looks like an implementation detail in month one and turns out to be load-bearing by month six.

Call one

The rules engine is data, not code

If rules live as Python if statements, the coach cannot touch them, every change needs a deploy, and the methodology stops growing — which breaks the central promise of the Monday Brief.

Rules belong in a table with a structured schema: trigger, evidence fact types, value method, confidence policy. Coach proposes, engineer reviews, no release required. Target 25–30 rules by week 8 and one a week thereafter — impossible at a deploy per rule.

Call two

Prompts are versioned artifacts with named owners

The coach owns the persona and style guide. Engineering owns the output schema and the reasoning contract. Both live in git, both have tests, both go through review.

Teams that treat prompts as configuration cannot explain a quality regression six months later — and on this product, “why did the brief get worse” is a question a customer will ask.

Call three

The verifier is infrastructure, not a feature. One library, its own test suite, imported by the Brief, the Analyst, the outbound audit, the Fleet P&L and every agent that writes a sentence containing a number.

It is the single component that makes all of it sellable into a market that has already named black-box distrust as its adoption blocker. Give it an owner and a changelog.

What not to build

Each of these is a quarter of two engineers' time, spent on something that buys nothing at this scale.

An agent frameworkSix well-defined agents do not need an orchestration abstraction. Scheduled jobs, good prompts, a queue.
A separate vector databasepgvector in the Postgres you already run. One fewer thing with its own backup story.
KubernetesFargate or plain VMs. Nothing here needs a scheduler with its own PhD.
MicroservicesA modular monolith. Two engineers cannot afford distributed-systems debugging.
A fine-tuned modelPrompt + rules + verifier beats a fine-tune here, and a fine-tune locks you to one model generation.
A custom RAG platformpgvector, sensible chunking, and citations back to the fact IDs you already have.
Streaming ingestionDaily grain is what every product surface needs. Batch is correct, cheaper, debuggable.
A model abstraction layerOne provider's SDK, prompts kept as data, call site in one module. That is the abstraction.
Rewriting the integrationsThe moat and the risk. This is the line the whole strategy rests on.

Two things to start before you need them

Both have long lead times and both will block a revenue moment if left until the moment arrives.

Week one, not week forty

The telemetry schema

Recommendations made, accepted, modified, rejected — and the outcome at T+7 and T+28 on the action's own scope. It ships before the features it measures.

It is the evidence base for outcome pricing, the training signal for the rules, and the thing that tells you which rules make money. It cannot be backfilled. Same argument as instrumenting disposals for Residual Radar: a month of delay is a month of history that never exists.

The ambush

ISO 27001

A franchisor's procurement will ask for it, and Network Edition is the largest GTM move on the table. Certification runs six to twelve months.

So it starts when the franchisor conversation starts — month one — not when the deal does. Otherwise the biggest single move in the plan stalls behind a certificate, at exactly the moment it is closest to closing.
